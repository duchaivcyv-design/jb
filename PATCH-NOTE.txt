ClaudeMini 0.7.4-1 (beta)

Chat:
- A reply no longer stops half way: if the connection drops, the stream closes quietly, or the model reaches its length limit,
  the app keeps the text already received and asks the model to continue (Claude and Gemini).
- Longer waiting time before a quiet connection counts as dead; the screen does not auto-lock while a reply is written.
- If iOS restarts the chat page during a reply, the text received so far is drawn again.

Mic:
- Tap the mic, speak, the words appear in the input box, then press send. Tap the mic again to stop.
- Voice choice, the Live screen and read-aloud were removed.

[Chat hang fix]
- GeminiStream/ClaudeStream: watchdog timer (live streams only). No first byte within 45-150 s (Gemini, by model) or 30-45 s (Claude), or silence mid-stream for 60-150 s: the task is cut and, if no text arrived, restarted silently on a fresh connection (max 2 times); otherwise finishes with a Network error so the existing continuation logic keeps the partial reply. Late callbacks of replaced sessions are ignored.
- Idle timeouts shortened (live 100/160 s, single request 180/360 s).

[Release]
- Official 0.7.4 (beta 0.7.4-1 promoted).

[Beta update row]
- Settings > Data has a "Bản cập nhật beta" row again: password prompt, then the usual update pop-up (no separate page). The Software Update page keeps only the automatic-check option and always uses the normal releases.

[0.8.0 beta 17]
- Material 3 stretch overscroll (as Android 12+) at the top and the bottom of every list and page (settings, history, model lists, key screen, font page, account screen...). In the Material design the rubber band that slid the content away is replaced by a stretch:
  * pulling past an end grows the content along the scroll axis (up to 28 %), anchored on the edge it is pulled from, with a resistance that grows with the distance (tanh curve); the content is not moved;
  * letting go springs it back, critically damped (stiffness 300, ratio 1), so it never shrinks below its natural size; catching it again while it springs back carries on from where it is on screen;
  * pulling back the other way gives the finger back to normal scrolling by exactly the distance that is left over;
  * a fling that runs into an end swells the content by an amount that follows the speed it arrived with (0.045 x speed, at most 16 % of the height, rising in 100 ms) and then springs back;
  * works for short content too (pull either way), nothing is stretched sideways.
  * Done on the layer (sublayerTransform about the visible edge), with no delegate: cells, headers and the account card stretch together. Off (the normal rubber band comes back) in the Classic design and with Reduce Motion.
- The chat page itself (a web view with its own scrolling) keeps the system overscroll.
- Not compiled or run on a device.
